# 📱 SNS 자동화 (인스타그램 · 스레드, 여러 계정)

인스타그램·스레드 계정 **여러 개**(브랜드·제품별 계정, 뷰티인포, 지역정보 등)에 글을 올리고 댓글에 답하는 자동화입니다.
처음에는 줌마렐라 카페(창원줌마렐라 · 김해줌마렐라) 이벤트를 **더줌** 계정으로 알리려고 만들었고(원래 저장소
`jingonpak-del/insta-thread-auto`), 이 폴더에서 계정을 여럿 다룰 수 있게 넓혔습니다.

| 계정 키 | 이름 | 상태 |
|---|---|---|
| `thezum` | 더줌 | 운영 중 (기본 계정) |
| `beautyinfo` | 뷰티인포 | 준비 중 — 꺼 둠, 모의 실행 |
| `localinfo` | 지역정보 | 준비 중 — 꺼 둠, 모의 실행 |

```
소재 등록 (계정 고르기 + 알릴 내용 + 사진, 또는 AI 이미지)
   ↓  Claude가 그 계정의 말투 가이드(brands/<계정키>.md)대로 채널별 초안 작성
확인 화면에서 읽고 고치고 [승인]
   ↓  비어 있는 발행 시각에 자동 예약
예약 시각에 인스타그램 · 스레드에 발행 (공식 API)
   ↓
30분마다 새 댓글 확인 → Claude가 답글 초안 → [승인하고 등록]  (나중에 '완전 자동'으로 바꿀 수 있음)
```

> 다른 계정에 좋아요를 누르는 기능은 **넣지 않았습니다.** 공식 API에 없는 기능이라
> 비공식 방법을 쓰면 계정 정지 위험이 있습니다.

## 매일 쓰는 법

1. 확인 화면 여는 법 (둘 중 하나)
   - **어느 컴퓨터·휴대폰에서든**: https://zumma.kr 에 로그인 → 위쪽 **📱 SNS자동화** 버튼
     → `https://sns.zumma.kr` 이 로그인된 채로 열립니다(12시간 유지). 주소를 바로 열면 "로그인이 필요해요"가 뜹니다.
   - **서버 컴퓨터에서**: **확인화면_열기.bat** 또는 http://localhost:3088 (로그인 없이 열림)
   - 버튼은 전 직원에게 보입니다. 특정 인원만 보게 하려면 업무관리 서버 `config.json` 의
     `snsUsers` 에 `["정다혜","임경아"]` 처럼 이름을 넣고 업무관리 서버를 재시작합니다.
   - 확인 화면 서버(포트 3088)가 꺼져 있으면 버튼을 눌러도 열리지 않습니다. 아래 **5) 자동 실행 등록**을 해 두면
     로그인할 때 자동으로 켜지고, 서버 감시(5분마다)가 꺼진 것을 발견하면 다시 켭니다.
   - 계정이 둘 이상 켜져 있으면 위쪽에 **계정 탭**(전체 계정 / 더줌 / 뷰티인포 …)이 생깁니다. 탭을 누르면 그 계정 것만 보입니다.
2. **소재 등록** — **올릴 계정**을 고르고, 알릴 내용(카페 공지, 사이트 글 등)을 붙여 넣고, 사진을 올리거나 'AI로 카드 이미지 만들기'를 체크합니다.
   1~2분 뒤(AI 이미지는 5~10분) **게시글 → 확인 대기**에 인스타·스레드 초안이 하나씩 생깁니다.
3. 초안을 읽고 고친 뒤 **승인**. 예약 시각을 비워 두면 비어 있는 가장 가까운 시각에 잡힙니다.
   - 📝 **확인할 점**: 소재에 없어서 Claude가 비워 둔 정보입니다. 꼭 읽어 주세요.
   - 빨간 상자(옛 카페 이름, 글자 수·해시태그 초과, 인스타 사진 없음)가 있으면 승인되지 않습니다.
   - 마음에 안 들면 **Claude에게 다시 쓰게 하기**에 "더 짧게"처럼 적고 다시 쓰기.
4. **답댓글** 탭에서 새 댓글과 답글 초안을 보고 **승인하고 등록** 또는 **건너뛰기**.
   - ⚠️ 직접 확인 필요: 불만·환불·당첨 확인·개인정보 같은 댓글입니다.
   - 광고·스팸 댓글은 자동으로 '건너뜀'에 들어갑니다.

### 발행 시각 (하루 게시 수)

`config.json` 의 `accounts` → 계정 → `slots` 에 채널별 시각을 적습니다.
**시각 개수 = 그 계정·채널의 하루 최대 게시 수**이고, 계정마다 따로 셉니다.

```json
"thezum": {
  "slots": {
    "instagram": ["11:30", "19:30"],
    "threads": ["08:30", "12:30", "21:00"]
  }
}
```

계정끼리 같은 시각에 올라가지 않게 시각을 조금씩 엇갈려 두세요(여러 계정이 동시에 같은 글을 올리면
Meta가 조작된 활동으로 보고 계정을 제한할 수 있습니다).

### 답댓글 완전 자동으로 바꾸기

확인 화면 **설정 → 답댓글 방식 → 완전 자동**. 이때도 '불만·민감·답하기 어려운 문의는 확인 대기로 남기기'를
켜 두면(기본값) 그런 댓글만 사람이 보고, 나머지는 바로 답글이 달립니다.

- 이 기능을 처음 켠 시각 **이전에 달린 댓글에는 답하지 않습니다**(예전 댓글에 한꺼번에 답글이 달리는 것을 막기 위해).

### 말투 바꾸기

**brands/<계정키>.md** (더줌은 `brands/thezum.md`)를 고치면 다음 글부터 반영됩니다. 맨 아래 **예시 글**에 실제로 마음에 드는
인스타·스레드 게시글을 붙여 두면 그 말투를 가장 잘 따라 합니다.

### 계정 추가하기 (제품별 계정 등)

1. `brands/_template.md` 를 `brands/<계정키>.md` 로 복사해서 채웁니다. 계정키는 영문 소문자(예: `product_a`)로 짓고 나중에 바꾸지 않습니다.
2. `config.json` 의 `accounts` 에 계정을 추가합니다. 처음에는 `"dry_run": true` 로 둡니다.

   ```json
   "product_a": {
     "dry_run": true,
     "name": "제품A",
     "who": "○○ 브랜드 제품A 공식 계정",
     "brand": "brands/product_a.md",
     "channels": ["threads"],
     "slots": { "threads": ["10:20", "16:40"] },
     "replace_words": []
   }
   ```

   - `channels` 에는 연결할 채널만 적습니다(스레드만 쓰면 `["threads"]`).
   - `replace_words` 는 쓰면 안 되는 말 → 바꿀 말 목록입니다(예: 옛 제품 이름).
3. 아래 **계정 연결**대로 토큰을 받아 `.env` 에 `PRODUCT_A_THREADS_ACCESS_TOKEN=` 처럼 넣습니다(계정키를 대문자로).
4. `python sns.py status` 로 `[제품A] 스레드: @아이디 연결됨` 을 확인하고, 모의 실행으로 글 몇 개를 만들어 본 뒤 `dry_run` 을 지웁니다.

- 뷰티인포·지역정보처럼 미리 넣어 둔 계정은 `"enabled": false` 로 꺼져 있습니다. 말투 가이드의 `(채워 주세요)` 를 채우고 토큰을 넣은 뒤 `true` 로 켭니다.

## 처음 한 번 준비 (연결)

`config.json` 맨 위의 `"dry_run"` 이 `true`(모의 실행)면 **모든 계정이 승인해도 실제로 올라가지 않고 기록만 남습니다.**
아래를 마친 뒤 `false` 로 바꾸면 실제 발행이 시작됩니다. (2026-10-27 부터 서버 컴퓨터는 `false` 로 운영 중)
계정 하나만 모의 실행하려면 그 계정에 `"dry_run": true` 를 넣습니다.

> 다른 컴퓨터에 새로 설치할 때는 **[docs/다른PC_설치와_작업기록.md](docs/다른PC_설치와_작업기록.md)** 를 먼저 읽어 주세요.

### 1) Claude 월구독 연결

글과 답글은 **Claude 월구독(Pro·Max)** 으로 씁니다. API 요금은 따로 나가지 않고, 구독 사용 한도 안에서 씁니다.

1. 이 컴퓨터 터미널에서 아래 명령을 실행합니다. 브라우저가 열리면 구독 중인 Claude 계정으로 로그인합니다.

   ```bash
   claude setup-token
   ```

2. 터미널에 나온 긴 토큰(`sk-ant-oat…`)을 `.env` 의 `CLAUDE_CODE_OAUTH_TOKEN=` 뒤에 붙여 넣습니다. **1년 동안** 유효합니다.
3. 구독 사용 한도에 걸리면 그 차례는 건너뛰고, 한도가 풀린 뒤 다음 차례(10분 뒤)에 다시 만듭니다.

> API 키로 바꾸고 싶으면 `config.json` 의 `claude_backend` 를 `"api"` 로 바꾸고 `.env` 의 `ANTHROPIC_API_KEY` 를 채웁니다.

### 계정 연결 — 토큰 이름

토큰은 **계정마다, 채널마다 하나씩** `.env` 에 넣습니다. 이름은 `<계정키 대문자>_INSTAGRAM_ACCESS_TOKEN`,
`<계정키 대문자>_THREADS_ACCESS_TOKEN` 입니다(예: `BEAUTYINFO_THREADS_ACCESS_TOKEN`). `.env.example` 에 틀이 있습니다.
더줌은 예전 이름 `INSTAGRAM_ACCESS_TOKEN` · `THREADS_ACCESS_TOKEN` 도 그대로 읽으니 서버 컴퓨터 `.env` 를 고칠 필요는 없습니다.

Meta 개발자 앱은 **하나만** 만들고, 아래 2)·3)의 '계정 추가' / 'Threads 테스터'에 계정을 하나씩 더 넣어서 계정마다 토큰을 받으면 됩니다.

### 2) 인스타그램 계정 준비

1. 인스타그램 앱 → 설정 → **계정 유형 및 도구 → 프로페셔널 계정으로 전환**(비즈니스 또는 크리에이터).
2. https://developers.facebook.com 에서 **앱 만들기** → 사용 사례에서
   **"Instagram에서 메시지 및 콘텐츠 관리"(Instagram API with Instagram Login)** 선택.
3. 앱 대시보드 → Instagram → **API 설정** → **계정 추가**로 더줌 인스타그램 계정을 연결하고
   **액세스 토큰 생성**. 권한은 `instagram_business_basic`, `instagram_business_content_publish`,
   `instagram_business_manage_comments` 가 필요합니다.
4. 나온 토큰을 `.env` 의 그 계정 토큰 자리(예: `THEZUM_INSTAGRAM_ACCESS_TOKEN=`) 뒤에 붙여 넣기.

> 내 계정에만 쓰는 앱이라 **앱 검수(심사) 없이** 개발 모드 그대로 쓸 수 있습니다.
> Meta 화면 메뉴 이름은 자주 바뀌니, 막히면 화면 캡처를 Claude에게 보여 주세요.

### 3) 스레드 계정 준비

1. 같은 앱(또는 새 앱)에 사용 사례 **"Threads API 액세스"** 추가.
2. 권한 `threads_basic`, `threads_content_publish`, `threads_manage_replies`, `threads_read_replies` 선택.
3. **역할 → Threads 테스터**에 더줌 스레드 계정을 추가하고, 스레드 앱 → 설정 → 계정 →
   웹사이트 권한 → 초대에서 수락.
4. 앱 대시보드의 **사용자 토큰 생성기**로 토큰을 만들어 `.env` 의 그 계정 토큰 자리(예: `BEAUTYINFO_THREADS_ACCESS_TOKEN=`)에 붙여 넣기.

> 계정이 늘어 다른 사람(직원·고객사) 계정까지 연결하게 되면, 개발 모드의 테스터 방식 대신 Meta 앱 검수(권한 심사)가
> 필요할 수 있습니다. 본인이 관리하는 계정만 테스터로 넣어 쓰는 동안은 검수 없이 됩니다.

### 4) 연결 확인 후 실제 발행 켜기

```bash
python sns.py status
```

계정·채널마다 `[더줌] 인스타그램: @계정이름 연결됨` 같은 줄이 나오면 `config.json` 의 `"dry_run"` 을 `false` 로 바꿉니다.
첫 게시글은 확인 화면에서 **지금 발행**으로 한 번 올려 보고 인스타·스레드에서 직접 확인하는 것을 추천합니다.

### 5) 자동 실행 등록 (작업 스케줄러)

PowerShell 에서 한 번 실행합니다.

```bash
powershell -ExecutionPolicy Bypass -File 작업스케줄러_등록.ps1
```

- `SNS자동화_10분` — 10분마다 예약 발행 · 초안 만들기 · 댓글 확인 · 토큰 갱신
- `SNS자동화_확인화면` — 로그인할 때 확인 화면 서버 켜기

**이 컴퓨터가 켜져 있어야** 예약 시각에 발행됩니다. 꺼져 있던 동안 지난 예약 글은 켜진 뒤 10분 안에 올라갑니다.

## 알아 두면 좋은 것

- **사진 주소**: 인스타·스레드는 사진을 인터넷 주소로만 받습니다. 발행할 때 사진을
  `../public/mom-img/sns-*.jpg` 로 복사해서 기존 `https://mom.zumma.kr/mom/img/` 주소로 내보냅니다
  (업무관리 서버 수정 없음). 그래서 **업무관리 서버(포트 3000)와 터널이 켜져 있어야** 발행됩니다.
- 인스타그램 사진은 세로 4:5 ~ 가로 1.91:1 비율이어야 해서, 벗어나면 흰 여백을 붙여 맞춥니다.
- **토큰**은 60일짜리이고 계정·채널마다 일주일에 한 번 자동으로 새로 받습니다. 컴퓨터를 두 달 가까이 꺼 두었다면
  토큰이 만료되니 새로 발급해 `.env` 에 넣어 주세요.
- 옛 카페 이름('마산맘', '김해줌마')은 Claude가 써도 자동으로 창원줌마렐라 / 김해줌마렐라로 바뀌고,
  손으로 넣으면 승인이 막힙니다(더줌 계정의 `replace_words`). 다른 계정도 같은 방식으로 금지어를 둘 수 있습니다.
- **여러 계정 운영 원칙**: 같은 소식이라도 계정마다 다른 글로 쓰고(말투 가이드가 다르니 Claude 초안도 다르게 나옵니다),
  계정끼리 서로 댓글·공유로 띄워 주지 않습니다. Meta가 조작된 활동으로 보면 계정이 함께 제한될 수 있습니다.

## zumma.kr 연결 (참고)

- 업무관리 서버 `server.js` 의 `authInject` — 📱 SNS자동화 버튼. 외부광고기록과 같은 서명 토큰(`extadSsoToken`)을
  붙여 `https://sns.zumma.kr/sso?t=…` 로 보냅니다. 설정은 업무관리 `config.json` 의 `snsUrl` · `snsUsers`.
- 이 프로그램의 `snsauto/web.py` 가 토큰을 업무관리 `config.json` 의 `internalSecret` 으로 확인하고,
  `employees.txt` 에 있는 직원만 들여보냅니다. 승인·발행·답글 등록은 `data/log.jsonl` 에 누가 했는지 남습니다.
- `C:\Users\admin\.cloudflared\config.yml` 에 `sns.zumma.kr → http://127.0.0.1:3088` 한 줄,
  `C:\Users\admin\클로드\server-watchdog.ps1` 감시 목록에 포트 3088 (`SNS자동화_확인화면` 작업)을 넣었습니다.

| `.env` | Claude 구독 토큰, 계정별 인스타·스레드 토큰 (**공유 금지**) |
| `brands/<계정키>.md` | 계정별 말투 가이드 (Claude가 그대로 읽음). `_template.md` 는 새 계정용 틀 |
| `작업스케줄러_등록.ps1` | 자동 실행 등록 |
| `snsauto/` | 프로그램 (writer=Claude 글쓰기, meta=인스타·스레드 API, jobs=예약·발행·댓글, web=확인 화면) |
| `data/materials.json` | 등록한 소재 (모든 계정 함께, `account` 로 구분) |
| `data/posts.json` | 게시글 (확인 대기 / 예약됨 / 발행 완료 / 실패 / 반려) |
| `data/replies.json` | 답글 |
| `data/log.jsonl` | 발행·오류 기록 |
| `data/uploads/` | 올린 사진과 AI 이미지 |
